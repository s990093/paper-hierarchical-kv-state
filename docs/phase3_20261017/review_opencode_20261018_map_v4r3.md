## 必改 1 的三個選項（給使用者）

- **(a) 重算也算錢**：對手放著 SSD 上的副本不讀、改重算時，照「這個長度下過關的最省格式」的大小算成讀取。這樣「丟掉 SSD 的副本」就不省讀取。
- **(b) 完美預測也知道「之後會不會從 SSD 讀」**：E1–E5 的 CPU 動態和 SSD 上存什麼格式無關，所以可以先跑一次記下「哪些 SSD 副本之後真的會被讀」，第二次把不會被讀的 SSD 副本壓成 INT2（兩次的 CPU 動態要完全一樣，不一樣就丟錯）。E6 和時間有關，只能近似，照實標出。
- **(c) SSD 不忙的格子不判**：看 C0 的 SSD 使用率；不到 5% 的格子 GO、NO-GO 都不算（上面第 5 條）。
- 審查也建議：做了 (a) 之後，護欄參考改回 C0。使用者 10/18 選 B（min(C0, O)）的理由正是這個漏洞；(a) 把漏洞直接補上，B 反而有「O 比 C0 快很多時連 C0 都被排除」的問題。
