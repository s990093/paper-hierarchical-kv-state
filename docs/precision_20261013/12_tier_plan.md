## 0. 要回答什麼

主線只量了「整段對話放在**同一層**」：全部在 CPU（真實 H2D），或全部在一個限速層。真實部署會遇到兩件主線沒量的事：

1. **容量**：CPU 記憶體放不下所有對話，多的要去 SSD／NFS。低精度讓同樣的記憶體多放幾段對話，「要去慢層」的時間點就往後推。
2. **一段對話分在兩層**：一部分 block 還在 CPU（BF16），一部分已經被降到慢層。降到慢層時才量化（04 號故事頁「延後」的設計），慢層那部分就是低精度。

要回答的問題：

- **A（IO 牆／容量，CPU 推算＋實測）**：
  - A1：同樣的記憶體，BF16／FP8／INT4 各放得下幾段對話？
  - A2：還原時間隨頻寬怎麼變？INT4 在某個頻寬的還原時間，等於 BF16 在多少頻寬的？（等效頻寬倍數）。頻寬高到多少時，低精度就不再省時間（損益兩平點）？
  - A3：記憶體固定、對話越來越多時，平均還原時間在哪裡開始往上衝（「牆」）？三種存法（全 BF16、全 INT4、分層：CPU 存 BF16、降到慢層才轉 INT4）的牆各在哪？
- **B（兩層混合還原，GPU 實測）**：一段 32K 的對話，有 25／50／75% 的 block 在慢層：
  - B1：慢層那部分存 INT4，比存 BF16 快多少？
  - B2：先降哪一段（最舊的、最新的、隨機）影響多大？
  - B3：和「全部都在 CPU、全 BF16」比，差多少？

## 1. 和主線、其他實驗的關係

- 主線（07）判完了，這裡的結果不能回頭改它的判定。
- 這裡沒有「位置策略」：「先降哪一段」是**儲存系統的淘汰順序**，不是依位置決定精度。慢層的精度一律相同（全 INT4 或全 BF16）。
- 品質：B 只量速度。INT4 KIVI 在 32K、兩個模型、所有位置都過 ε（08 §2.5.3、§2.6），所以這裡不重量品質。慢層讀到的 INT4 block 是 E1 的子集〔推論：子集不保證一定更好，但主線的混合配置（16 個 INT4 block）也都過〕。限制寫在 §4。
- 64K／128K：10 號計畫的 stage 90 會量 64K／128K 的速度格子（CPU＋三個限速層）。拿到之後，A1–A3 用同樣的程式重算一次（§2.4）。

### 2.2 推算模型與驗證（寫死）

- 用 `m10_sweep_sim.simulate`，也就是 Cake 的兩條線。每個 block 在頻寬 B 的載入時間：
  - `l_i(B) = max(位元組_i ÷ B, h_i) + d_i`
  - h_i：CPU 層實測的只載時間扣掉反量化。d_i：反量化時間（BF16 為 0）。
- **驗證**：拿主線 b16／b32／b48 的實測 cake 中位數比，門檻沿用 09 §5（會合點在 ±1 內 ≥ 90% 的格子、還原時間誤差中位數 ≤ 5%）。B 跑完後，再用 6.98／0.331 GiB/s 的實測比一次。沒過門檻：只畫實測點，不畫推算曲線。
- **寫死的用法**（同 09 §5）：
  - 推算只用在頻寬 ≤ 7 GiB/s 的範圍。
  - 頻寬更高（12、20 GiB/s、CPU 層）一律用實測，因為推算沒算到反量化和重算搶 GPU，在 CPU 層一律偏快 3–19%。
  - **損益兩平點只從實測點算**：在 log 頻寬上，對相鄰兩個實測點線性內插。

### 2.3 輸出（寫死）

- **A1 容量表**〔算術〕：每段對話的大小（32K／64K／128K × BF16／FP8／INT4），以及 256 GiB、512 GiB、1 TiB、2 TiB 的主機記憶體各放得下幾段。
- **A2 牆的曲線**：每個模型、GPU 閒／忙，還原時間對頻寬（log 軸，0.3–50 GiB/s），E0、E1-FP8、E1-INT4 三條線。
  - 實測點用實心，推算的線用虛線。
  - 數字：等效頻寬倍數 k(B)，也就是 E1 在 B 的時間＝E0 在 k·B 的時間；在 0.331、1、3、6.98 GiB/s 報。另外報損益兩平點 B×。
- **A3 溢出模型**：
  - 主機記憶體 M（同 A1 的四種）、N 段長度 L 的對話。在 CPU 的比例 p＝min(1, M ÷（N × 每段大小））。
  - 平均還原時間＝p × T_CPU ＋（1−p）× T_慢層。
  - 三種存法：

    | 存法 | CPU 裡存 | 慢層存 |
    |:--|:--|:--|
    | 全 BF16 | BF16 | BF16 |
    | 全 INT4 | INT4 | INT4 |
    | 分層 | BF16 | INT4 |

  - T 用實測：CPU 層用主線格子，慢層用 B 的參考點。
  - 畫平均還原時間對 N 的曲線。**「牆」定義為平均還原時間超過「全部都在 CPU、全 BF16」的 2 倍時的 N**。報每種存法的 N_牆，以及全 INT4、分層對全 BF16 的倍數。
- 慢層兩種：SSD 級 6.98、NFS 級 0.331 GiB/s。

### 2.4 假設（寫死，報告要列）

- 每段對話一樣長；每段回來的機率一樣（均勻）；A3 裡一段對話整段在同一層（部分降級是 B）。
- 慢層只有一個，頻寬固定；沒有寫入干擾。只算還原時間，不算寫入、壓縮的時間。
- 64K／128K 等 stage 90 跑完再算；在那之前只報 32K。

## 3. B：兩層混合還原（GPU，`code/m10_tier2.py`，stage 44）

### 3.1 配置

- 32K（64 個 block），兩個模型，Cake 還原（主線同一個還原器，`m7_restore_harness.Restorer`，每個 block 有自己的層：`loc[i]`）。
- **兩層**：
  - CPU 層：pinned 記憶體、真實 H2D、不限速，存 BF16。
  - 慢層：同一份 pinned 記憶體加限速器，頻寬 6.98 或 0.331 GiB/s。
- **兩層配置**（每個慢層頻寬 18 個）：
  - 降級比例 f ∈ {25%, 50%, 75%}（16／32／48 個 block）。
  - 降級順序：
    - **舊**：block 0 到 k−1，最舊的先降，像整段對話的 LRU。
    - **新**：最後 k 個，像 vLLM 前綴樹先淘汰尾端。
    - **隨機**：從 64 個裡抽 k 個，每次重複換一組。
  - 慢層的精度：BF16 或 INT4（int4_kivi，主線第 2 階的格式）。
  - 名稱：`T<舊|新|隨>-<f>-<bf16|int4>`，程式裡是 `Told25-bf16`、`Tnew50-int4`、`Trnd75-int4`。
- **參考點**：
  - 每個慢層頻寬：全部在慢層 BF16、全部在慢層 INT4。
  - CPU 層：全部 BF16（E0）、全部 INT4（E1）。
  - 牆的中間點：全部 BF16／全部 INT4 在 1、3、12、20 GiB/s 的限速層（給 A2）。
- GPU 閒／忙（忙＝主線同一個背景負載 busy2）。
- 2 個 launch × 每格 5 次（同 10 號計畫的速度格子）；同一次重複裡配置順序隨機打散。每個（配置, 層, GPU 狀態）第一次還原時檢查 KV（`kv_bad`：重算／BF16＝參考、INT4＝原寫法 decode，逐位元）。
- 反量化用主線的原寫法（`M10_DEQUANT_FAST` 不開），和主線格子可以直接比。
- 載入線照主線：一條線、從最後一個 block 往前、一次一個；它不會跳過慢層的 block 先去讀 CPU 的。

### 3.2 每次還原記什麼

主線 `restores.csv` 的欄位，另外加：慢層頻寬、慢層有幾個 block、從慢層／CPU 各載了幾個（`n_load_ssd`、`n_load_cpu`）、兩層各花多少時間（`t_load_ssd`、`t_load_cpu`）。逐 block 的來源與起訖時間寫進 `blocks.csv`。

### 3.3 事先寫的預期（探索；寫的時候沒有任何數字）

- **B1**：同樣的比例和順序，慢層存 INT4 比存 BF16 快。NFS 級的差距比 SSD 級大；比例越高，差越多。
- **B2**：最便宜的是「舊」，因為 Cake 的重算線從前面做，最舊的 block 多半被重算蓋掉，不用從慢層讀；最貴的是「新」，因為載入線從後面開始，一開始就碰到慢層；「隨機」在中間。
- **B3**：「舊 25%」不管慢層存什麼，都在「全部 CPU、全 BF16」的 δ\* 內〔推論：16 個最舊的 block 大部分會被重算〕。
- **B4**：分層（慢層 INT4、CPU BF16）時，CPU 那部分還是 BF16，所以不會碰到「CPU 層反量化變慢」（11 問題一）；全部 INT4 才會。

### 3.4 怎麼報（寫死）

- 每格：還原時間中位數、會合點、從兩層各載了幾個 block、讀了多少位元組、反量化時間。
- 比較都用同一次重複裡相鄰量的配對差，bootstrap 95% CI（同主線 `m10_speed.compute_delta`）。「快」＝中位數差 > δ\*、而且 CI 不含 0。δ\* 用主線的（Llama 5%、Qwen 9.43%）。
  - B1：同 (順序, f, 慢層, GPU) 的 INT4 對 BF16。
  - B2：同 (f, 精度, 慢層, GPU) 的「舊」對「隨機」、「新」對「隨機」。
  - B3：每個兩層配置對 CPU 層 E0。
- 圖：每個慢層頻寬 × GPU 狀態一張，x＝降級比例，y＝還原時間，線＝順序 × 精度。
- 寫進 08 的新一節（「兩層混合還原」，標「探索，12 號另外登記」）、RUNLOG Milestone 13。

## 4. 限制（先講）

- 慢層是限速模擬（pinned 記憶體＋計時器），不是真的 SSD／NFS：
  - 沒有檔案系統、讀取延遲、真的「SSD → 主機 → GPU」兩段搬運。
  - 頻寬用第一階段的實測值。
- 載入線一次只讀一個 block、照固定順序。真實系統可能同時從兩層讀，或先讀快的那層，那會更快；這裡量的是「不改還原器」的情況。
- B 不量品質（§1）。
- 只有 32K（64K／128K 的兩層混合還原沒排；要的話另外登記）。
- 慢層的 INT4 只有 KIVI 一種；FP8 在 Qwen 品質不過（08 §2.3），所以不放。
- A3 的工作負載是最簡單的假設（§2.4），不是真實 trace。
