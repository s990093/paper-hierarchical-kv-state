## 1. 怎麼量（一段話版；細節見 07）

- **兩個模型**：Llama-3.1-8B-Instruct、Qwen2.5-7B-Instruct-1M，BF16 權重；context 固定 64 個 block × 512 token＝32K。
- **配置**：E0（全 BF16）、E1（全低精度）、E1s（block 0 保留 BF16）、E1sr（block 0 和最後一個保留）、F25／M25／B25（前／中／後 16 個 block 低精度）、R25（隨機 16 個）。同樣存量，只換低精度放哪。
- **兩種讀法**：A＝64 個 block 全部從儲存載入（量「敏感度」）；B＝Cake 實際還原，在會合點 b 前重算、b 之後載入（量「實際品質」）。B 用 b32 頻寬、GPU 閒／忙／第 2 輪才變忙。
- **格式**（20 題小測只看 KL 選，07 §3）：Llama FP8 每 token 一個 scale、Qwen FP8 每 head 一個 scale；INT4 兩個模型都用 KIVI 式。
- **判準**：品質＝主任務 T2–T5 對 E0 的配對正確率差，95% CI 下界 > −2 個百分點，且每個任務族、每一輪的點估計 ≥ −5；速度＝不輸最快的混合配置 ×(1＋δ\*)。δ\*：Llama 5%、Qwen 9.43%。
- **限制先講**：「慢層」是 pinned 記憶體加限速器，不是真的 SSD／NFS；GPU 忙＝背景 matmul duty 0.7；還原器的重算比 vLLM 慢（§5.2 這輪沒修，§2.7 有對照表）。

## 5. 限制

- 「慢層」是限速器，不是真的裝置；只叫「限速層 X GiB/s」。
- MLSteam 是單一 VF 的容器：GPU 本身的外來 process 看得到（3 個 process 都 CLEAN），**同一台 host 上其他容器對 PCIe／host 記憶體的負載看不到**（`gpu_guard` 記成 `UNOBSERVABLE_HOST`，每一列都是）。δ 量的是實際的變動，判勝門檻已經包含它。
- 還原器的重算比預設 vLLM 慢 1.7–2 倍（第一階段 F1）；重算快 2 倍時會合點會往後移，F25「沒被讀到」的情況會更明顯〔推論，引 F7 的模擬〕。
- 只有一個長度（32K）做品質；8K／16K 只量速度。長 context（64K／128K）另外登記成探索實驗，排在所有 32K 工作之後（[10](10_longctx_plan.md)，使用者 10/16 決定）。
- 合成題（RULER 式）＋ LongBench 只報告；不是真實對話。
