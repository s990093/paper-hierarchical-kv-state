# F0P：共享前綴的優先權反轉（F0 加兩個優先級，CPU 模擬）

> **性質**：判準登記。登記時間見文末「登記」一節（`date -u`）。登記之後這一節以上不改；和登記不同的做法寫成文末的「偏離 N」。
> **來源**：2026-10-26 用 OS 死結四條件檢視推論系統的結果：四條件裡只剩「互斥被共享打破之後的協調」可能還有空白，具體就是**優先權反轉**。高優先請求去重到一個由低優先請求發起、還在途中的共享還原上，就會被低優先的排隊拖住。模型與常數沿用 [F0_follower_sim.md](F0_follower_sim.md)。
> **這一關回答**：
> 1. 有兩個優先級（高 H、低 L），而且兩條線都依優先級排程時，H 的共享請求的 TTFT P95 被反轉拖慢多少？
> 2. OS 的解法「優先權繼承」能消掉多少？
> 3. LLM 才有的兩個逃生路，在某些格會不會贏過繼承？一是不去重、自己用 H 載一份；二是自己用 H 重算。
> **結論的等級**：全部是〔模擬〕。GO 只代表值得往下查，不是結果。

## 1. 模型（`code/s3/kvs_f0p.py`）

### 1.1 沿用 F0（不改 `kvs_f0.py`，直接 import）

- **兩條線**：計算線一條、載入線一條（每個 tier 一條）。每個項目開始之後不中斷。
- **常數**：F0 §1.2 全部。用 `kvs_f0.consts`、`f_of`、`t_new_of`、`t_load_of` 計算，所以和 F0 的尺準（F0-CAL PASS）是同一組數字。
- **共享前綴 P**：n 塊，放在一個 tier。
- **共享請求**：N 個，第 0 個（owner）在 t＝0 到，其餘在 [0, spread·W_load] 均勻亂數（排序後），W_load＝n·t_L。
- **量測窗**：[0, H]，H＝最後一個共享請求到達時間＋W_load＋5 s。P 還原完之後留在 HBM。
- **別人的工作**：每個是 c_o 秒的計算項目，Poisson 到達。
- **干擾**：只用 none（k_rec＝k_load＝1）。

### 1.2 新增的部分

| 項目 | 模型 |
|:--|:--|
| 優先級 | 每個請求（共享請求含 owner、別人的工作、背景載入請求）各自獨立以機率 h 為 H，否則為 L。用另一條亂數流抽，所以同格、同 seed 的所有策略看到相同的到達與優先級 |
| 計算線排程 | 取 (優先級, bundle, 準備好的時間, 序號) 最小的項目：H 先於 L。同一級內照 F0：共享請求的新一輪排在其他項目前面（bundle），之後先到先服務 |
| 載入線排程 | 每次要開始一塊時，從還沒載完的還原裡挑 (有效優先級, 進佇列的序號) 最小的一份，載它的下一塊（從後面往前，同 F0）。同一級內就是 F0 的先到先服務、一份載完再換下一份。H 的還原在塊的邊界插到 L 前面，正在載的那一塊不中斷 |
| **背景載入請求**（新） | 別人的請求，各有一段**私人**前綴（長度同 P，n 塊），從同一個 tier 載入，載完做一次新一輪 t_new(n)（計算線，非 bundle）。Poisson，到達率 λ_b＝ρ_b ÷ max(n·t_L, t_new(n))，也就是它在自己瓶頸那條線上的使用率是 ρ_b。不去重、不被幫忙 |
| 別人的工作（改） | 到達率 λ_o＝max(0, ρ_o − λ_b·t_new(n)) ÷ c_o，所以 ρ_o 是「計算線上非共享工作的總使用率」，背景載入的新一輪也算在內。若 λ_b·t_new(n) > ρ_o，實際使用率就是 λ_b·t_new(n)，照實寫進輸出（`util_c`） |
| **暖機**（新） | 別人的工作與背景載入從 −T_w 開始到達，T_w＝20×max(W_load, t_new(n), c_o)。這樣 owner 在 t＝0 到時，系統已經有正常的排隊。只量 [0, H] 內到達的請求，但模擬跑到所有請求做完為止 |
| 共享還原 R 的有效優先級 | **不繼承**：等於 owner 的優先級，固定不變。**繼承**：取 owner 與目前在等 R 的跟隨者中最高的。H 跟隨者一加入就升級，之後開始的塊與幫忙項目都用新的等級 |

### 1.3 策略（6 個）

L 跟隨者在所有策略裡都等（去重）。H 跟隨者遇到「有效優先級是 H 的在途 R」時也是等。表格最後一欄只管一種情況：H 跟隨者到達時，R 還在途中，而且 R 的有效優先級是 L。

| 代號 | 共享規則（基底） | R 的優先級 | H 跟隨者遇到 L 的在途 R |
|:--|:--|:--|:--|
| A4 | F0 的 P4：去重＋bundle，不幫忙（Strata 式） | 不繼承 | 等 |
| I4 | 同上 | **繼承** | 等（R 因此升到 H） |
| D4 | 同上 | 不繼承 | **自己用 H 載一份**私人的 P，不去重 |
| C4 | 同上 | 不繼承 | **自己用 H 整份重算**（F0 的 P2 式，一塊一個 H 項目） |
| A5 | F0 的 P5：去重＋bundle＋一律幫忙（Cake 式），是 F0 的 R* | 不繼承 | 等 |
| I5 | 同上 | **繼承** | 等 |

A5／I5 的幫忙項目用 R 的有效優先級。計算線挑項目時，若 R 還有塊沒做，**而且**（計算線佇列是空的，或 R 的有效優先級不低於佇列裡最好的項目），就幫忙（重算 R 前面的下一塊）。所以 H 的 R 在所有項目之前幫忙；L 的 R 只在沒有 H 項目排隊時幫忙，但排在 L 項目之前，和 F0 的「幫忙優先於別人的工作」一致。

### 1.4 量什麼

- **主要量**：H 共享請求（含 owner 是 H 的情況）的 TTFT P95，記為 `hsh_p95`。每格、每個策略把 40 個 seed（0–39）的請求合起來算。F0 用 20 個 seed；這裡 H 只佔約三成，所以加倍。
- **只報告**：
  - 暴露的 H 跟隨者的 P95（`hexp_p95`）：owner 是 L 的 episode 裡、不是 owner 的 H 共享請求。這個定義和策略無關。
  - 所有 H、所有 L、全部請求的 P95，用來看繼承對別人的副作用。
  - 重算塊數、載入塊數、λ_o、λ_b、`util_c`、`util_l`、T_w。
- 樣本數 < 20 時，該格的 `hsh_p95`（或 `hexp_p95`）寫 `NOT_MEASURED`，不進判定，報告時列出被排除的格數。

## 3. 判準

先定義三個量：

- **反轉的代價**（以繼承當「沒有反轉」的對照）：
  - inv4(格)＝hsh_p95(A4)÷hsh_p95(I4)−1
  - inv5(格)＝hsh_p95(A5)÷hsh_p95(I5)−1
- **逃生路對繼承的改進**：esc(格)＝1−min(hsh_p95(D4), hsh_p95(C4))÷hsh_p95(I4)。正的表示自己載或自己算比繼承好。

**先過自測（不過就不跑，回報、問人）**：

- (a) h＝0（全是 L）或 h＝1（全是 H）、ρ_b＝0、不暖機、餵 F0 的到達序列時：
  - A4、I4、D4、C4 每個請求的 TTFT 都和 `kvs_f0.simulate(..., "P4")` 相同；
  - A5、I5 都和 `"P5"` 相同；
  - 差 < 1e-9，每個 tier × 每個 L 都要成立。
- (b) ρ_b＝0 時 inv4 恰好是 0：載入線上只有 R，R 的優先級不影響任何事。
- (c) 守恆：每份還原的每一塊恰好做一次；每條線同一時間只做一件事；請求在到達前不開始。

**決定性實驗**：

| 結果 | 條件 |
|:--|:--|
| **STOP-P（當場）** | 12 格的 inv4 與 inv5 都 < 5%。在這個模型裡反轉可以忽略，全網格不跑 |
| 繼續 | 其他情況 → 跑全網格 |

**全網格的判定**：用 Llama 的兩個面板判定，Qwen 的兩個面板只當重現；只用 hsh_p95 有效的格。先算兩個條件：

- (E) 反轉夠大：inv4 > 15% 的格數 ≥ 有效格數的 10%。
- (X) 逃生路有用：esc > 5% 的格數 ≥ 有效格數的 10%。

| 結果 | 條件 |
|:--|:--|
| **GO-P** | 兩個平台都 (E) 且 (X)。值得設計「繼承／自己載／自己算」的選擇規則並另外登記；在那之前先查真實 trace 的 ρ_b |
| **INHERIT-ONLY** | 兩個平台都 (E)，但都不 (X)。反轉是真的，但教科書的繼承就夠了，沒有 LLM 特有的東西。這條線當研究停止，記為負面結果 |
| **STOP-P** | 兩個平台所有有效格的 inv4、inv5 都 < 5% |
| 問人 | 其他 |

- **一併報告（不判定）**：
  - 繼承的副作用：I4 對 A4，L 請求 P95 變差 > 5% 的格數，以及所有 H 請求 P95 的變化。
  - inv5、`hexp_p95` 的同一組比較。
  - D4、C4 各自最好的格子在哪。
  - ρ_b＝0 的格當健全檢查：inv4 應該是 0。
- **預期與循環風險**（登記前就寫下）：
  - 在這個模型裡，反轉的大小主要由「R 前面排了多少 L 的背景載入」決定，也就是 ρ_b 與 tier 的速度，基本上是排隊算術。
  - 所以 (E) 成立只代表「真實的 ρ_b 夠大時，反轉會很大」。真實系統的 ρ_b 是 `NOT_MEASURED`，T0 沒有量優先級，Mooncake trace 也沒有優先級欄位。
  - (X) 才是有沒有 LLM 特有東西的那一條。
- **沒有模擬的**：
  - 載入線完全不看優先級（真實 connector 的傳輸順序沒有查證）；
  - 中斷正在載的那一塊；
  - 一個 episode 裡有多段共享前綴；
  - decode、HBM 容量、跟隨者中途改變主意。
