## 1. 模型（`code/s3/kvs_f0.py`）

### 1.1 資源

| 資源 | 模型 |
|:--|:--|
| GPU 計算線 | 一條、不可搶占（以「項目」為單位）。項目有三種：重算 P 的第 i 塊（f(i) 秒）、某個請求的新一輪（t_new(L)）、別人的工作（c_o） |
| 載入線 | 每個 tier 一條、先到先服務；每塊 t_L＝chunk_bytes÷頻寬 |
| 干擾 | 主設定互不干擾（k_rec＝k_load＝1）；敏感度（只報告）：(1.06, 1.0)（I1 interf 量到 MI300X 重算 ×1.063）、(1.0, 1.5)（08 §2.1 的算術） |

### 1.2 常數（全部從檔案讀，記進輸出）

| 常數 | H200 | MI300X |
|:--|:--|:--|

| c_o（別人的工作） | Σ_{i=60..63} f(i)：32K context 尾端 2K 新 token 的 prefill | 同左 |

### 1.3 一個 episode

- 共享前綴 P：n 塊，放在一個 tier。N 個共享請求：第 0 個在 t＝0 到，其餘在 [0, spread·W_load] 均勻亂數（排序後）；W_load＝n·t_L。spread＝0 時全部在 0 到。
- 別人的工作：Poisson，到達率 λ_o＝ρ_o÷c_o，時間範圍 [0, H]，H＝最後一個共享請求到達時間＋W_load＋5 s。
- 量的是 [0, H] 內到達的**所有**請求（共享請求＋別人）從到達到完成（新一輪或 c_o 做完）的時間 TTFT；跑到它們全部做完。
- P 還原完之後一直留在 HBM（這個 episode 內）；等待窗 Δ＝0。（候選 C 的 Δ 與 TTL 不在這一關。）
- 每格 20 個 seed（0–19），所有 seed 的請求合在一起算 P95 與平均。

### 1.4 策略

計算線的預設順序：依「準備好的時間」先到先服務。

| 代號 | 規則 | 對應 |
|:--|:--|:--|
| P0 | 不去重：每個共享請求各自把 P 整份載一次（載入線先到先服務），載完才做它的新一輪 | vLLM 不開 prefix caching |
| P1 | 一律等：第一個請求載 P（只載入）；在途時到的跟隨者等，載完後新一輪依到達順序排進計算線；之後到的直接命中 | vLLM #29087 |
| P2 | 在途時到的跟隨者一律自己整份重算（第 0 塊到第 n−1 塊，一塊一個項目，前一塊做完才排下一塊），之後做新一輪；owner 照樣載入 | #44295 的「一律回 0」 |
| P3 | 跟隨者到達時，計算線忙或有排隊 → 等（P1），否則 → 自己重算（P2） | #44295 的規則（以「計算線有沒有壓力」實作，是我們的解讀） |
| P4 | P1＋bundle：P 到了之後，等 P 的新一輪排在別人的工作前面 | Strata 式（delay hit＋bundle；載入期間別人照跑＝bubble filling） |
| P5 | 去重＋bundle＋**一律幫忙**：載入線從 P 的後面載，計算線從前面重算 P（Cake 的雙指標，相遇即完成），而且幫忙的項目優先於別人的工作 | Cake 套在共享前綴上 |
| **P6** | 去重＋bundle＋**依成本幫忙**：計算線每次挑項目時，若 P 還沒相遇，令 i＝下一個要重算的塊、W＝正在等 P 的共享請求數、Q＝計算線上排隊的別人的工作數；**W·t_L ≥ Q·f(i)** 就重算第 i 塊，否則做排隊的第一個項目 | 本提案 |
| P7 | 每格事後取最好的：{P0…P6} ∪ {P6 的門檻乘上 θ：W·t_L ≥ θ·Q·f(i)，θ∈{0.25, 4, ∞}} | 只報告（上界） |

P6 的直覺：重算第 i 塊要 f(i) 秒，會讓 Q 個排隊的人各晚 f(i)；它省下一塊的載入，讓 W 個等 P 的人各早 t_L。GPU 閒（Q＝0）時就是 Cake。

## 3. 判準

**先過尺準 F0-CAL（不過就不判定，回報、問人）**：
- (a) 邏輯：N＝1、ρ_o＝0 時，P5 的還原時間和 `m16_mcake.simulate([Sess(n)], "rr", f, t_load)` 相同（差 <1e-9），每個 tier、每個 L 都要（自測）。
- (b) 對實測：L＝32K、N＝1、ρ_o＝0 時，P5 的 TTFT ÷ `summary_fp8.csv` 的 E0 cake 32768 idle `median_ttft`，在有實測的 tier（cpu、b16、b32、b48；後三個只在尺準時用 bw.json 的 `targets`）裡，每個面板至少 3／4 個落在 [0.9, 1.1]。

**決定性實驗（先跑）**：面板 (H200, Llama)，tier∈{cpu, nvme, nfs} × L∈{8K, 128K} × ρ_o∈{0, 0.8}，N＝16、spread＝0.5，共 12 格。

| 結果 | 條件 |
|:--|:--|
| **STOP-F（當場）** | 12 格的「最好的固定規則」（P0–P5 中 P95 最小者）全部是同一條，**而且** P6 對它的改進在 12 格都 <5% |
| 繼續 | 其他情況 → 跑全網格 |

**全網格的判定**（Llama 的兩個面板判定；Qwen 的兩個面板只當重現）：
- R*（每個平台一條）＝P0–P5 中，P95 對 324 格取幾何平均最小的那一條固定規則。
- gain(格)＝1 − P95(P6)÷P95(R*)。

| 結果 | 條件 |
|:--|:--|
| **GO-F**（做 F1） | 兩個平台**都**：(i) gain > 15% 的格 ≥ 10%（≥33 格）；(ii) 沒有任何一格 gain < −5%；(iii) 每格最好的固定規則不是全部同一條 |
| **STOP-F** | 兩個平台都所有格 gain < 5%；或兩個平台的 (iii) 都不成立 |
| 問人 | 其他（含 (ii) 不成立：P6 在某些格明顯變差） |

- 一併報告（不判定）：P6 對「每格最好的固定規則」、對 P7 的差距；平均 TTFT 的同一組比較；共享請求與別人分開的 P95；干擾敏感度。
- **I1 的教訓**：好處可能只來自排隊順序。P4、P5、P6 都有 bundle，只差「要不要幫忙」，所以 P6 對 P4（從不幫）與 P5（一律幫）的差距，就是「依成本幫忙」本身的價值，報告時單獨列。
- **循環風險**：P6 的規則是在同一個模型裡想出來的；GO 只放行 F1，任何主張都要等 F1。
