KV 放置決策儀表

六個動作、兩種成本、四種策略。拉動下面的控制項，看哪一個動作在什麼條件下勝出—— 以及哪一個在什麼條件下根本不該被選。

01

每個動作有兩種成本，不是一種

「平時成本」是這個狀態閒著時佔多少 GPU 記憶體； 「取回成本」是被需要時要花多久才能用。兩者性質不同，不能壓成一個數字。 只看取回成本會得到「重算最貴所以永不重算」的錯誤結論。

block 位置 8,192
勾起來才看得到 SSD 與重算的真正競爭

重算的成本隨位置線性成長：4.008 + 0.00021 × 位置 ms/block。 實測 C(P) = 513.0 ms + 26.9 ms × (P/1000)，線性擬合最大偏差 1.6%， 五個量測點全在線上——不是二次成長。

02

SSD 與重算的優劣，在 7,277 token 處反轉

SSD 的取回成本是常數（5.54 ms/block），重算隨位置成長。兩條線必然相交， 而交叉點決定了「該存還是該丟」。

04

Decode 每一步都要讀完整個 KV，所以卸載在那裡不可行

prefill 一次算 N 個 token，KV 只讀一次；decode 一次算一個， 但每一步都要把整個 KV cache 讀一遍。同一筆搬運， prefill 攤在 12 萬個 token 上，decode 每個 token 都要付一次。

後果：三種工作負載的有效動作空間不同。 prefill 為主與多輪對話可用六階全部； 生成為主只剩 GPU 內的精度階，CPU/SSD 慢 3–59 倍。 後者唯一的出路是稀疏 attention（只取回當步分數高的 block）， 而那時預測的是 attention 分數而非存取機率——不同的預測問題。
