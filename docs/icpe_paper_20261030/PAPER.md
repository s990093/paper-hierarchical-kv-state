## 摘要

> ⏳待決（敘事框架，使用者決定；內文照 (A) 寫）：
> - **(A，建議)**「預知的價值取決於 trace：在真實 agent trace FreeInference 上，oracle 上界在每個 CPU 容量都 <15%；在 Mooncake（conversation 與 toolagent）上常 ≥15%，免費訊號蓋得到預取、蓋不到淘汰順序。」貢獻變成「預知在哪裡值得的實測地圖」＋不用預知的收益。
> - **(B)** 把論文收窄到 FreeInference＋chat 的預取，Mooncake 的淘汰順序寫成未解的例外。
> - 舊論點「收益來自位元組，不是預知」當成全稱句已不成立：Mooncake 上 X1 的 192 格裡 95 格 ≥15% [B9]。

多輪對話與 agent 讓 KV cache 在請求之間停在 CPU DRAM 或更慢的儲存層；請求回來時，還原時間直接算進 TTFT。近期系統在 KV 管理上加入預測（PBKV、CacheScout、Continuum、KVFlow 等）並報告大的收益；Liu 等人在真實的 FreeInference trace 上發現淘汰策略的命中率離 Belady 很遠。這些結果都是在「沒命中就重算」的設定下量的（預測系統的部分依摘要判斷）。Cake 不需要預測就能還原：前段在 GPU 重算、後段從儲存層載入、在中間會合。**在 Cake 之上，預知還值多少？** 我們在一張 H200 上做 limit study：把預知分成寫入時、回來時、還原時三種，各用 oracle（完美預測器）量它對同動作、最好的不預知對手的 TTFT 上界；門檻事先登記；用三條真實 trace（Mooncake conversation、Mooncake toolagent、FreeInference）。模擬器的 CPU 層與重算常數在 H200 上量，SSD／NFS 級是沿用 MI300X 常數的限速模擬；模擬以 GPU 縮小重播檢查（TTFT 不含排隊時，實測÷模擬 0.911–0.987，排序與正負號全同）。結果是一張地圖。寫入時依位置決定層級，在 GPU 上量不到收益（0/16 個 GPU 列）；還原方式用固定的分層規則就夠。回來時的預知取決於 trace：在 FreeInference 上，X1 的 oracle 在 CPU 16–1,024 GiB 都 <15%（≥128 GiB 時 ≤0.30%，因為 CPU 命中 99.29%，不是差距被吸收）；在 Mooncake 兩條 trace 上，192 格裡 95 格 ≥15%，截尾並排除寫入飽和後仍有 36 格，CPU 到 512 GiB 都有。打字提示（提前量是合成的）蓋得到預取：1/8 縮小重播、SSD 級上拿到 oracle 預取改善的 0.81／0.79；淘汰順序沒有對應的免費訊號（NOT_MEASURED）。不用預知的已知做法裡，INT4 讓限速慢層的還原快 36.7–54.5%（CPU 層不會），MPS 的 SM 預留是拿背景吞吐換前景延遲的取捨。

## 1 引言

**傳統看法**：預測能讓分層 KV 更快。知道誰會回來就先預取，知道誰不回來就先丟，知道哪些 KV 重要就放在快的層。近期系統把這些預測做進 KV 管理（PBKV、SAGA、CacheScout、CacheWise、Continuum、KVFlow），都報告了大的收益。Liu 等人（*When Fancy Eviction Fails*）在 FreeInference 上發現，花俏的淘汰策略贏不了 LRU，但離 Belady 的命中率還很遠。

**什麼變了**：這些收益的對照組是「沒命中就重算」（Liu 等人讀了內文；預測系統只讀了摘要，待核對）。實際的服務會把 KV 停在 CPU DRAM 或更慢的層，而 Cake 不需要任何預測就能從那裡還原。miss 的代價變了，預知的價值也可能跟著變。

**問題**：
- **RQ1**：在 Cake 之上，寫入時、回來時、還原時三種預知的 oracle 上界各是多少？在哪些 trace、哪些容量？
- **RQ2**：上界高的地方，免費訊號拿得到多少？
- **RQ3**：不用預知的話，什麼值得加？

**答案**（完整計分見 §9 表 7）：
- 寫入時：依位置決定層級，GPU 上量不到 TTFT 收益；依位置決定精度，同樣位元組下沒有穩定的品質收益（§4）。
- 回來時：**看 trace**。FreeInference 上 X1 在 CPU 16–1,024 GiB 都 <15%；Mooncake 兩條 trace 上 95/192 格 ≥15%（§5、§7）。打字提示蓋得到預取；淘汰順序沒有免費訊號比過（§5.3）。
- 還原時：固定的分層規則就夠，線上選擇器常選錯（§6）。
- 不用預知的：INT4 在限速慢層有效；MPS 是取捨（§8）。
- ⏳待決：框架 (A)／(B)（見摘要上方）。

**貢獻**：
1. 在 Cake 之上量預知上界的 limit study：三條真實 trace、同動作的最好對手、事先登記的門檻；模擬經 GPU 縮小重播檢查，實測÷模擬 0.911–0.987（conversation、SSD 級、Llama、TTFT 不含排隊）[B6]（§3）。
2. 回來時預知的地圖：FreeInference 上 X1 在 CPU 16–1,024 GiB 0 格 ≥15%，X5 在 128–1,024 GiB ≤2.44% [B3-X1、B3-X5、B3-T5]；Mooncake 上 95/192 格 ≥15%，含 CPU 512／1,024 GiB 與 SSD 級，截尾＋不飽和後 36 格 [B9]（§5、§7）。
3. 免費訊號的範圍：打字提示在 GPU 上拿到 oracle 預取改善的 0.81／0.79 [C2-GPU]；淘汰順序的免費訊號 NOT_MEASURED [B1-ORD]（§5.3）。
4. 通往 Liu 等人的橋：同一段 FreeInference 上，命中率差距與「沒命中就重算」的 TTFT 差距沒有在同一個容量同時出現（BRIDGE-NO-GAP）[B3-T4]（§5.1）。
5. 寫入時與還原時的負面結果：GPU 0/16 列 [A2]；固定規則 24 格 0 翻轉 [A5]；更強的規劃器判定字 0 改變 [R-T3]（§4、§6）。
6. 已知做法在 H200 上的量測：INT4 讓限速慢層還原快 36.7–54.5% [D2]；MPS 端到端可判的 24 格 0 格過門檻 [S2]（§8）。

## 2 背景與系統模型

- **KV 停在哪**：每個回合結束時，整個 session 的 KV 以 BF16 寫進 CPU 層；CPU 層滿了，就挑一個 session 以 INT4 降到慢層，或丟掉（回來時重算）。block＝512 token，32K context＝64 塊；BF16 每塊 Llama 67,108,864 B、Qwen 29,360,128 B [§0]。
- **還原算進 TTFT**：請求回來時，前綴的 KV 要先回到 HBM，新的 token 才能開始 prefill。
- **三種還原方式**：全部載入、全部重算、Cake（GPU 從第 0 塊往後重算，I/O 從最後一塊往前載入，兩邊相遇就結束）。b16／b32／b48 三個限速層就是「會合點在第 16／32／48 塊」的頻寬 [§0]。
- **還原的底**：GPU 上量到的最佳做法是一條固定的分層規則（慢層 Cake；CPU 層 INT4 全部載入、BF16 在 GPU 忙時 Cake）[A5]。**模擬器（X1）沒有實作這條規則**：它把 Cake 用在整個前綴，CPU 與慢層的塊混在一起，從前面重算、從後面依位置讀 CPU 或慢層 [§0]。差別對 headroom 的影響 NOT_VERIFIED。
- **三個插入點**：① 寫入時（放哪層、存什麼精度）；② 回來時（預取、淘汰順序、丟棄）；③ 還原時（挑還原方式）。§4–§6 依這個順序排。

![](figs/fig1_system.svg)

**圖 1　還原時間在 TTFT 裡，三種預知各自只能改變其中一段。** KV 在回合結束時進 CPU 層，滿了以 INT4 降到慢層或丟掉。圖中的「固定分層規則」是 GPU 量到的最佳做法（§6）；模擬器把 Cake 用在整個前綴（§2）。

## 3 方法：limit study

**oracle 階梯**。每個問題都在同一條 trace 上跑四種臂：底（Cake）→ 最好的對稱對手（同樣的動作、不預知）→ 免費訊號（打字提示）→ oracle（完美預知一件事，其他照對手）。oracle 是同類預測器的上界：

> headroom＝1 − T_oracle ÷ T_對手；T＝回來請求的平均 TTFT。Mooncake 的 X1 每格取兩種 session 重建規則（R1、R2）中較小的值；FreeInference 只有資料自帶的 session_id；X5 用它自己登記的規則。

**對手只在同動作的集合裡挑** [§0]：O-ORD 對 LRU、LRU2、ARC、S3-FIFO、GDSF、PENS；O-DROP 對 LRU、LRU+NONE、LRU+2HW、LRU+2HA；O-NOW 對 LRU、LRU+NONE、LRU+2HW；O-PF 只對 LRU、LRU+RPF（見 §5.2 的 B1-R）。

**表 1　三種預知與本文的 oracle**

| 預知 | 決定的時刻 | oracle 事先知道什麼 | 不預知的對照 | 具名前作 | 節 |
|:--|:--|:--|:--|:--|:--|
| 寫入時 | 回合結束、降層那一刻 | 每塊之後會不會被讀 → 依位置定層級與精度 | 延後決定（S4+）；最好的不看位置策略 | SARIA、Gandalf〔摘要〕；ICPE'25 *Better Memory Tiering*〔只核對書目〕 | §4 |
| 回來時 | 兩次請求之間 | 誰回來、何時回來 → 預取（O-PF）、淘汰順序（O-ORD）、丟掉不回來的（O-DROP、O-NOW）、知道誰不回來（X5） | 同動作的對稱策略；打字提示預取（HINT-PF） | PBKV、CacheScout、Continuum、KVFlow〔摘要〕；CachedAttention | §5、§7 |
| 還原時 | 請求到達 | 各還原方式的實際成本 → 挑最快的 | 固定的分層規則 | CacheFlow〔摘要〕；我們自己的線上選擇器 G5b | §6 |

**判定規則（事先登記）**。δ\*＝max(5%, 雜訊)。某元件在同一（trace, 慢層, GPU）、Cake、≥2 種 CPU 容量下 ≥15% →「有看頭」；所有格 <5% →「死路」；其他 →「可能」。品質的 ε＝95% CI 下界 ≥ −2 個百分點 [§0]。登記檔在看到數字之前 commit；和登記不同的做法寫成「偏離」。

## 4 寫入時的預知〔實測〕

**主張：寫入時依位置決定層級，對 TTFT 沒有可量到的收益；依位置決定精度，在同樣位元組下沒有穩定的品質收益。**

- **為什麼**〔判讀〕：Cake 從前段重算，前段存成什麼精度、放在哪層，大多不會被讀到。前段降精度的品質「好」，是因為那段沒被讀到，不是放對了位置 [A4]。

- **範圍**：寫入准入對 SSD 寫入量與壽命的好處（SARIA、Gandalf）不在本文的量測範圍。

**發現與含意**：「第一次就放對」對 TTFT 不成立；寫入端可以保持簡單。

## 5 回來時的預知：取決於 trace〔模擬〕

**主張：在 Cake 之上，回來時 oracle 的上界在 FreeInference 上每個 CPU 容量都 <15%；在 Mooncake 的兩條 trace 上常 ≥15%。免費的打字提示蓋得到預取，蓋不到淘汰順序。**

## 6 還原時的預知：固定規則就夠〔實測；STAIR 是模擬〕

**主張：每一層的最佳還原方式是固定的；依當下狀況線上挑還原方式沒有空間，反而常選錯。**

- **固定規則不翻轉**：重算換成更快的 fa3（sdpa 的 0.75 倍）後，24 格 0 翻轉，1 格弱變化（Llama、CPU 層閒、BF16：平手 → 全部載入）。慢層 16 格全是 Cake，比全部載入快 16.5–87.5%；CPU 層 INT4 全部載入勝或平手，BF16 在 GPU 忙時 Cake 勝（Llama 0.152 vs 0.238 s、Qwen 0.068 vs 0.236 s）[A5]。微基準加上像真實服務的背景負載，最快的還原計畫也和閒時相同（0 翻轉；雜訊太大不判的 379 格、NOT_MEASURED 84 列不在內）[S1]。
- **線上選擇器常選錯**：G5b 在 CPU 層、GPU 忙時，原本 12 格裡 10 格比最好的慢 1.31–3.51 倍。換 seed 310／311 重跑：4 格兩次都 >1.05 倍、5 格只有一次、1 格都沒有 → **部分穩定**。24 個（格 × seed）裡全部載入都比 Cake 慢 1.52–3.52 倍，G5b 卻有 30–100% 的次數選了全部載入 [E3]。
- **更強的規劃器也不改判定**〔模擬〕：STAIR（照 CacheFlow 的想法寫的簡化規劃器，不是 CacheFlow 本身）下 11 個判定檔 0 個字改變；chat 的 oracle headroom 少 2.3–7.6 pp。回來請求的 STAIR÷Cake 中位 SSD 0.953／0.935、NFS 0.491／0.625 [R-T3]。
- ⏳待決：STAIR 例外句（建議寫法：「SSD 級回來請求 ≥99.4% STAIR ≤ Cake；其餘 20/3,511（CPU 128 GiB）、16/3,511（256 GiB）最多慢 2.05／2.28 倍；NFS 級 0 個」）。不寫「STAIR 處處 ≤ Cake」。

**發現與含意**：在 GPU 還原上，固定分層規則已經是調好的底；線上選擇器多付了出錯的風險，換不到時間。

## 8 不用預知的收益：已知做法在 H200 上值多少〔實測；MPS 端到端是模擬〕

這兩件都是已知做法（4-bit KV 卸載、固定 SM 預留）。我們只量它們在 H200 上值多少，以及它們不需要預知。

### 8.1 INT4：位元組小 3.2 倍，限速慢層的還原變快

- 每塊位元組：Llama 67,108,864 → 20,971,520 B；Qwen 29,360,128 → 9,175,040 B [D1]。
- 還原時間（32K；b16／b32／b48 × 閒／忙）：Llama 快 37.4–49.1%、Qwen 快 36.7–54.5%；12 格全部 INT4 勝，污染列 0 [D2]。
- **CPU 層不會變快**：Llama 忙 −39.4%、閒 +13.0%（沒過 δ\* 28.4%）；Qwen 閒 −21.9%、忙 −80.0% [D2]。〔判讀〕CPU 層夠快，反量化的成本蓋過省下的傳輸。
- **不重複計算**：D2 是隔離的還原微基準。§5 的模擬底已經把降到慢層的 KV 存成 INT4，所以這個收益已經在底裡，不能和 §5 的 headroom 相加。
- 品質：32K、192 題，INT4 對 BF16 Qwen +0.4 [−1.1, +2.2]、Llama +1.0 [−0.4, +2.7] pp，兩個都過 ε [D2-Q(a)]。多鍵 NIAH＋LongBench-6（對照路徑）：Llama 四種讀法都過；Qwen 讀法 A 過，GPU 忙的兩種讀法 −0.8 [−2.2, +0.3] 沒過 ε [D2-Q(b)]。⏳待決：主引 (a)、(b) 寫明 Qwen 的讀法條件。
- 再壓更小不划算：低秩＋INT4（8–17 倍）多數配置品質沒過 ε [D3]；在慢層比 INT4 快只有 6/8 格，b32、GPU 忙時反而慢（0.56–0.63 倍）[D4]。

### 8.2 MPS：延遲換背景吞吐的旋鈕

- **微基準**〔實測〕：18 格比 stream 共享快 ≥30%，背景吞吐比 ≥0.91；最強一格 4.28 倍（CI [4.26, 4.29]），背景比 0.980 [S1]。

**預測型 KV 管理。** PBKV、CacheScout、CacheWise、Continuum、KVFlow 都報告預測帶來大的收益。從摘要看，沒有一篇的對照組是「分層儲存＋Cake 還原」。若讀內文確認，本文能說的是：換成 Cake 之後，預知剩下的空間取決於 trace——FreeInference 上 X1 在 CPU 16–1,024 GiB 都 <15%，Mooncake 上 192 格裡 95 格 ≥15%（§7）。

**limit study 與 oracle 上界。** Liu 等人在同一條 FreeInference 上說「花俏的策略贏不了 LRU、但離 Belady 遠」。表 4 和他們不衝突：沒有一個容量同時有命中率差距與 TTFT 差距，CPU ≥128 GiB 時兩者都接近 0。另一方面，FreeInference 的小容量 NFS 格裡，S3-FIFO 的 TTFT 比 LRU 明顯好（oracle 對 LRU 17.7–29.2%，對 S3-FIFO 只剩 5.6–11.8%），方向和「贏不了 LRU」不同；〔判讀〕指標（TTFT vs 命中率）與容量區間都不同。*Where Should the KV Cache Live?* 說預取 oracle 也沒用，和我們 conversation 上預取上界高的結果相反；〔判讀〕可能的原因是合成 workload、沒命中就重算、PCIe 爭用。

**還原機制。** Cake 與 CacheFlow 回答「怎麼還原更快」；我們量的是「依狀況線上挑還原方式」值多少，結論是固定規則就夠（§6）。

**寫入准入與分層。** SARIA、Gandalf 的寫入時決定改善 SSD 寫入量與壽命；ICPE'25 *Better Memory Tiering* 主張分層記憶體要「第一次就放對」（只核對書目）。我們的反向結論只限於 TTFT（§4）。

**已知做法與免費訊號。** 4-bit KV 卸載與固定 SM 預留業界已在做；本文只貢獻它們在 H200 上的量測與「不需要預知」這一點（§8）。打字提示是 *Ask the Tool*（agent 端）與 CachedAttention（排程佇列）在使用者端的對應，而且只涵蓋預取。

## 11 結論

⏳待決：框架 (A)／(B)（見摘要上方）。照 (A)：

多輪 KV 還原的時間直接算進 TTFT。在 Cake 之上，預知值多少取決於 trace：真實 agent trace FreeInference 上，X1 的 oracle 上界在每個 CPU 容量都 <15%；Mooncake 的 conversation 與 toolagent 上，192 格裡 95 格 ≥15%。免費的打字提示在 GPU 縮小重播上拿到 oracle 預取改善的 0.81／0.79，但淘汰順序還沒有免費訊號。寫入時與還原時的預知沒有空間；INT4（限速慢層）是不用預知的收益，MPS 是取捨。這張地圖告訴設計者哪裡不必蓋預測器，哪裡值得蓋。
