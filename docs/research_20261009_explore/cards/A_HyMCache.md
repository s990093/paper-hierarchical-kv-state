# A_HyMCache A CXL Memory Rack for Multi-Turn LLM Serving（HyMCache）

- **出處**：Hakbeom Jang, Inho Song, Hoshik Kim, Sam H. Noh, Jongryool Kim。arXiv 2607.18141v3（v1 2026-07-20）。venue：未查證。<https://arxiv.org/abs/2607.18141>。讀了 p.1–6、p.10（PDF 實體頁；只讀了和寫入、預取有關的段落）。
- **寫入時做了什麼決定**：**什麼時候寫、要不要寫**。CXL-HM（少量裝置內 DRAM＋大量 SSD，掛在 CXL 介面後面）在裝置 DRAM 裡留一小塊寫入緩衝；**只有緩衝有空時才收新的 KV 物件；緩衝滿了，runtime 可以跳過這次寫入或稍後重試**。收下的物件延後、以大批次非同步刷到 SSD 區，「最好在讀取壓力低時」〔原文 p.6〕。
- **用什麼資訊做決定？（N1）**：緩衝是否有空、讀取壓力。不是 N1。原文的觀察：多輪對話的寫入是 append-only，每輪只寫新生成的 token 的 KV〔原文 p.5〕；KV 寫入只影響未來的重用，不影響當前請求的正確性〔原文 p.6〕。
- **有沒有和延後版、寫穿版、背景版比較？**
  - 對照組是本機 LMCache（CPU 快取）、GPU prefix caching、1 TB DRAM 的分散式 Mooncake、RDMA NVMe-oF 儲存〔原文 p.1、p.10〕。同樣 DRAM 預算下，比本機 LMCache 快 3.0 倍（單節點）、1.45 倍（P/D 分離）；比 1 TB Mooncake 慢約 30%，但 DRAM 少 16 倍〔原文 p.1〕。
  - **關鍵的副作用（原文自己報的）**：讀取優先的策略「延後了寫入緩衝的排空，在這個負載下**跳過了超過 15% 的潛在 KV 插入**」，這限制了命中率的提升〔原文 p.10〕。
- **硬體**：真實的 CXL-HM 原型（FPGA 型，原文說成本是四個 FPGA 原型的粗估）〔原文 p.3 註腳〕；單一 aggregator 配一個 A100 worker；P/D 分離設定每個 worker 64 GB、共 256 GB〔原文 p.2、p.4〕；RDMA 100–400 Gbps〔原文 p.3 Fig.〕。
- **模型架構、模態**：文字多輪對話（原文 p.1–6 沒讀到模型名稱，未查證）。
- **和本研究的關係**
  - **N3 的實例（支持）**：延後／背景寫入需要空閒；讀取壓力高時沒有空閒，延後的寫入就**直接被丟掉**（>15% 的插入被跳過）〔原文 p.10〕。這正是「寫入時有、之後就沒有」的時機版本：當下沒寫，之後就沒機會寫〔判讀〕。要注意它的代價是「少命中」，不是「請求被擋住」——和 Screen 的 H0 結論（真實系統 CPU 滿了就不存）同一個形狀〔判讀，見 `../H0_offload_blocking.md` §0〕。
  - **H12（CXL 三層）**：CXL 層在這裡是「DRAM 緩衝＋SSD」的混合裝置，延後寫入發生在裝置內部；這篇沒有做「寫入時決定直接寫 SSD 區還是留在裝置 DRAM」〔判讀〕。H12 的「延後搬要搬兩次」在它的設計裡被裝置吸收了。
  - **H11（P/D）**：P/D 分離設定下，prefill 節點把新 KV 用 RDMA 寫到遠端 CXL 機櫃〔原文 p.3〕——prefill 節點的傳輸本身就是一次寫入，與 10 §3C 的描述一致〔判讀〕。
