K1 只看 KV 本身的幾何，不是答對率，但它決定了後面哪些壓縮值得試：

  • K 在加位置資訊（RoPE）之前很低秩（保留 1/4 維度誤差約 25%，95% 能量只要 36–40 維），而且用前 4K token 算的基底套到後面幾乎不變差；RoPE 之後就不低秩、也不能事先算基底。V 本身不低秩（95% 能量要 108–110 維）。所以低秩一定要在 RoPE 前做，V 要靠別的方法（量化）。
  • 相鄰層同一 token 的 KV 完全不像（cosine ≈ 0），MiniCache 式的逐 token 跨層共用沒有依據，照事先條件停。但「多層一起找共用方向」（xKV）不受影響——X1 之後證實它是最好的家族。
  • 相鄰 token 看起來像，主要是共同的平均方向；扣掉平均後真正很像的不到 1%，合併相似 token 沒什麼可省（X1 也證實合併會崩）。

K1b（10/22 補）：「相鄰層不像」和「跨層低秩有效」怎麼同時成立；Tucker 多一個維度有沒有用

  • 跨層共用的是 token 子空間，不是向量：相鄰層同一 token 的 cosine ≈ 0（兩個模型、K／V 都是），但每層前 64 個左奇異向量張成的子空間重疊很高（去平均：Llama K 0.76、V 0.69；Qwen K 0.67、V 0.63；隨機 0.002）。每一層有自己的 WK，所以兩層的「第 c 個通道」不是同一個座標，cosine 自然 ≈ 0；但兩層的輸入都是幾乎相同的殘差流，「哪些 token 一起變化」很像。這解釋了 MiniCache 式的逐 token 共用沒用、xKV 式的共用子空間有效。前人已經寫過（xKV 原文；JoLT 用同一個量分組），這裡只是在 32K 上重新量到。
  • Tucker 多出來的維度沒有額外幫助：4 維 Tucker（token × 層 × head × 維度）在同位元組下的誤差幾乎等於「全部層一組的 xKV」——數學上也是這樣：只有 token 那一維的因子隨長度變大，而同一個 token 秩下最好的就是全部層一起做 SVD；層、head、維度三個模態要「跨層共用座標」，但相鄰層座標不同（上一點），所以接近滿秩（和 arXiv 2609.28029 的結論相同）。兩側分解（token 跨層共用＋每層各自的通道基底）也沒幫助。
  • 真正有用的是「一組放更多層」：同位元組下，xKV 每 4 層 → 每 8／7 層，重建誤差約 0.82–0.91 倍；V 的收益比 K 大。最佳的組大小不一定是全部層（Llama 的 K 每 16 層最好）。GPU 上的 teacher forcing（4.14）：每 8／7 層在 Qwen 一致較好、Llama 分不出；全部層一組好壞參半。
