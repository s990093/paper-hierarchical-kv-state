vLLM 這組回答「在真實的 serving 系統裡，復用與卸載什麼時候划算」，三個實驗都沒有被干擾。

  • V0：vLLM 0.28 在 MI300X 上，APC、CPU 卸載、ROCm 修補、SSD 分層都能跑；命中與不命中的輸出只在「前兩名機率完全相同」的位置分歧（數值平手），不是快取把 KV 弄錯。第一次執行時 job 對這種分歧太嚴而停下，修正後重跑（失敗 5）。
  • F2（共用前綴、大量併發）：vLLM issue #44294 的「開卸載慢一倍」在 MI300X 上沒有重現——和同一個注意力後端比，開卸載打平或更快。真正的代價是開了 CPU 卸載後 vLLM 在 ROCm 上會強制改用較慢的 TRITON 注意力，高併發時慢約一倍。
  • F1（重疊 × 容量 × 到達 × 設定）：APC 的收益只由重疊決定（50% 重疊少 20–62%、100% 少 76–93%），容量和到達率幾乎不影響；照事先條件字面判「成功」，但找到的「沒收益區域」只有重疊 0%，是當然結果。比較有用的是 CPU 卸載的邊界：8K 的提示開卸載幾乎都變慢（容量緊、負載高時平均 TTFT 慢一倍以上），32K 才變快（+3～15%）。

合起來：在 AMD 上，CPU 卸載值不值得，取決於提示長度、注意力後端的退回、以及搬運路徑（I4：逐塊 copy 只有 1–3 GiB/s）。這些都是候選 3「AMD 上的快速 KV 還原路徑」的直接證據：如果搬運與後端的成本降下來，8K 的卸載邊界就會往有利的方向移動。
