這一輪不是要做出一個方法，而是幫第三階段選題目。大問題沿用前兩階段：KV 放不下 GPU 時，要依什麼決定它的待遇——降精度、無損壓縮、搬到 CPU／SSD，還是丟掉（之後重算，或依重要性直接不要）。

四幕故事

  1. 依位置（前兩階段）：依位置決定放哪一層、用多少位元，都贏不過「晚點再寫」和「隨機挑」；整份降到 INT4 答對率幾乎不掉。這條走到底了。
  2. 依內容（使用者的問題①：KV 量化、依 token 重要性決定）：重要性能不能省空間（丟 token 對上量化）、能不能省搬運（只還原需要的 block）；10/20 起擴大成「各種壓縮能不能疊起來用」。
  3. 依場景（使用者的問題②：要不要改 agent）：agent 暫停時 KV 閒著，但只有顯存不夠時才是問題。
  4. 依現場狀況（這次新加）：前人假設「拿回來要多久」是固定的；第二階段量到 GPU 忙時重算慢約一倍、搬運慢約一半。

這一輪實際回答了什麼

  • 問題①：依重要性丟 token 在同樣位元組下全面輸給量化，而且多輪會壞；重要性比較像「還原時挑要搬哪些」的訊號，但目前便宜的挑法（Quest 摘要）不夠準。真正把位元組省下來又不掉分的，是跨層低秩＋量化的疊加（第 4.6–4.11 節）。
  • 問題②：MI300X 192 GB 在 agent 工作負載下沒有容量壓力，這次不改場景（第 4.12 節，模擬）。
  • 現場狀況：還原端的實測顯示「最快的壓縮格式」會隨 GPU 忙碌翻轉（第 4.9 節），這是第三階段最有新意的線索之一。
