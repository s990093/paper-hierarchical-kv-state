把五種壓縮放在一起看

KV 大小 ＝ token 數 × 層數 × 每個 token 的維度 × 每個數的位元 ÷ 無損倍數。這一輪把每一項都試過：

  • token 數（依重要性丟、合併）：同位元組下全面輸給量化，多輪更糟（丟一半 block 第 2 輪掉 17–19 個百分點）。
  • 層數（逐 token 跨層共用）：相鄰層完全不像，沒有依據。
  • 維度（低秩）：單獨用、每層各自做都不好；跨層一起做（xKV 式）＋K 在 RoPE 前是唯一有效的形狀。
  • 位元（量化）：INT4 是單一方法的甜蜜點（3.2 倍、不掉分）。
  • 無損：再小 1.1–1.5 倍，只在慢的下層划算。

真正有加乘的是「維度 × 位元」兩項的疊加（再乘無損）：約 8 倍接近無損、12 倍掉 1–3 個百分點、32 倍掉 7–8。和單用 INT4 相比，同樣答對率下大約多省 2.5 倍位元組；和只降秩相比，高倍數時答對率高出 8–25 個百分點。

省下的位元組換不換得到時間

  • 寫入：每題 SVD 要數十秒，不實用；事先校準的共用基底在答對率上看不出變差（但還不能證明不輸），是實用化的關鍵。
  • 還原：慢的下層（SSD、NFS）上，低秩組合把還原時間壓到 BF16 的 1/3 左右；CPU 記憶體層、GPU 閒時也比 INT4 快一點。
  • GPU 忙時：低秩重建是一次矩陣乘，會和模型計算搶 GPU，忙時慢約 2.8 倍；實測在 CPU 層、GPU 很忙時「低秩＋INT4」比不壓縮還慢。→ 最佳格式隨 GPU 忙碌翻轉。前人知道解壓會搶 GPU（ShadowServe、KVCodec、Tutti），但用靜態隔離避開；把執行期 GPU 忙碌當成選格式的輸入，查新沒找到（L7b）。
