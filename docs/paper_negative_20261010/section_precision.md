## P.1 問題：精度和放置不一樣

第一部分的結論是：KV 放哪一層，延後決定就追得上，因為寫入時用到的資訊（位置）延後一樣拿得到。

精度看起來不同：
- 一個 block 存成 FP8 或 INT4，就回不去 BF16。放置可以「先放 CPU、滿了再搬」，精度沒有對應的「先存高精度、之後再降」——除非多存一份。
- 所以精度是「提早決定」最可能有不可取代價值的地方。文獻也常依位置配精度：保護開頭（attention sink）、保護最近的 token（KIVI、KVQuant、SKVQ、QEvict、PM-KVQ）〔原文；卡片 P03〕。

**但在 Cake 式還原下，有一件事會混淆「位置有用」的證據**：一個 block 的精度只有在**它被載入時**才影響品質。被重算的 block 一律是精確的 BF16。會不會被載入，由會合點決定，而會合點是讀取時才知道的（GPU 忙不忙、層的頻寬）。所以「把低精度放在前段，品質沒掉」可能有兩種原因：
- **不敏感**：那一段壞一點，答案不會錯；
- **沒被讀到**：那一段被重算了，低精度備份根本沒用到。

這一部分把兩者分開量，並回答三個問題：
1. 全部用低精度（均勻）夠不夠？不夠的話，是 sink、格式，還是位置的問題？
2. 前段量化沒掉品質，是不敏感，還是沒被讀到？
3. 同樣的位元組下，依位置配精度比隨機配好多少？

## P.2 方法

### P.2.1 配置：同樣的位元組，只換低精度放哪裡

context 固定 64 個 block × 512 token＝32,768 token，問題接在後面。每個配置都存滿 64 個 block，差別只在每個 block 是 BF16 還是低精度：

| 配置 | 低精度的 block | 作用 |
|:--|:--|:--|
| E0 | 無 | 品質上限 |
| E1 | 全部（含 block 0） | 均勻低精度（老師的端點；Cake＋均勻量化） |
| E1s | 1–63 | 已發表的「保護 sink」規則 |
| E1sr | 1–62 | 已發表的「保護開頭＋最近」規則 |
| F25／M25／B25 | 1–16／24–39／48–63 | 依位置：前、中、後，各 25% |
| R25 | 從 1–63 隨機抽 16 個（seed＝題號） | 同比例、不用位置的對照 |

- **sink 一律控制**：除了 E1，block 0（token 0–511，涵蓋文獻說的 1–32 個 sink token）一律 BF16。不控制的話，「前 25% 低精度」會連 sink 一起壓，前後比較就混了 sink 效應。sink 本身用 E1 對 E1s 單獨量。
- **attention 路徑完全相同**：低精度 block 載入後先反量化成 BF16，寫進同一個 BF16 KV 緩衝，用同一個 attention kernel。不用硬體的 FP8 attention（那會換 kernel）。
- F25、M25、B25、R25 存的位元組完全相同；**不同的只有實際讀到的位元組**，那正是要量的。

### P.2.2 兩種讀法：把「敏感度」和「讀取機率」分開

| 讀法 | 怎麼還原 | 回答 |
|:--|:--|:--|
| A：強制全載入 | 64 個 block 全部從儲存載入 | **敏感度**：低精度放在這裡，答案會不會錯 |
| B：Cake 實際還原 | 前段重算、後段載入，在會合點 b 停；b 由速度實驗量出（每個配置 × 頻寬 × GPU 閒／忙） | **實際品質**：在真實的會合點下讀到多少低精度、品質掉多少 |

- 還原器逐 block 記錄來源：重算（精確 BF16）、載入 BF16、載入低精度。
- **讀法 B 用「重放」量品質**：重算出來的 KV 和原本 prefill 存的 BF16 逐位元相同〔實測：test_m7_correctness〕，所以給定 b，block < b 放原本的 BF16、block ≥ b 放存的版本，就等於真的跑 Cake。我們在 50 題（Llama FP8）、50 題（Qwen FP8）、20 題（Qwen INT4）上比對「真的跑 Cake」和「重放」：KV 與問題的 logits 逐位元相同（最大差 0.0），會合點 b＝15–36〔實測 pilot selfcheck〕。
- **兩輪**：第 2 輪的歷史固定成標準答案（所有配置相同），問另一個位置帶。兩種第 2 輪：留在 GPU 直接重用；或換成 GPU 忙、再還原一次（會合點往前移，前段的低精度開始被讀到）。

### P.2.3 題目

- RULER 風格的合成任務，加上「把需要的資訊放在指定位置帶」的參數：T1 多鍵撈針、T2 一鍵多值、T3 變數追蹤、T4 兩跳 QA（HotpotQA 的兩段 gold 段落放進位置帶）、T5 常見詞聚合（全文統計，沒有位置帶）。位置帶：前（block 1–16）、中（24–39）、後（48–63），和低精度的位置刻意對齊，形成「答案位置 × 低精度位置」的交叉。
- **難度只用 BF16 調**：每個模型、任務族、位置帶的 BF16 正確率要落在 60–95%（不碰天花板、模型本身會做）。T1 兩個模型都碰天花板，只報告不判定。
- 題數：T1–T4 各 180 題（每個帶當第 1 輪、第 2 輪各 60 次），T5 60 題，共 780 題。主判準用 T2–T5。
- 外部效度（只報告）：LongBench v1 的 6 個資料集（≤32K），各 50 題，官方截斷與計分。

### P.2.4 模型與格式

- 模型：Llama-3.1-8B-Instruct（Cake、KIVI、ZipCache 都用的模型）、Qwen2.5-7B-Instruct-1M（KVTuner、DiffKV 報告「Key 特別怕量化」的家族），BF16 權重。
- **低精度格式事先用另一批 20 題選定**（只看 E1 對 E0 的平均 KL，不看答對率）：

| 模型 | FP8 e4m3（scale 每個 block 自己算）| INT4 |
|:--|:--|:--|
| Llama | 每 token 一個 scale（KL 0.0024；每 head 0.0043、每 channel 0.0041） | KIVI 式（K 每 channel、V 每 token，group 32；KL 0.0052） |
| Qwen | 每 head 一個 scale（KL 3.4；每 channel 8.8、每 token 11.8） | KIVI 式（KL 0.0125） |

〔實測 fmtsel：`20261015-160426`…`-160811`〕

- **換格式的診斷**（只在均勻 FP8 不夠時才判讀）：E1-K0＝K 先減掉每（block, 層, head, channel）的平均再做 FP8（平均另存 BF16）；E1-INT8＝每 token 每 head 對稱 INT8。兩者都保留 block 0 BF16。

### P.2.5 速度

- 層：CPU＝pinned 記憶體、真的 H2D（實測 49 GiB/s 左右）；「慢層」＝同一份 pinned 記憶體加限速器，**只叫「限速層 X GiB/s」**，不宣稱是哪一種裝置。限速器依每個 block 的實際位元組計時（低精度 block 只算它的位元組）。
- **頻寬用會合點選，不用裝置名稱選**：量逐 chunk 重算曲線 f(i)，取 B＝(64−b*)×block 位元組÷Σ_{i<b*} f(i)，讓 E0 的會合點落在 b*＝16、32、48（「多半在搬」「一半一半」「多半在算」）。Llama：5.27／1.47／0.42 GiB/s；Qwen：2.77／0.76／0.22 GiB/s〔實測 calibf〕。
- GPU 忙：背景 matmul，duty 0.7（第一階段量過：重算慢 2.07 倍）。
- 每格 3 次重開 process × 10 次，同一次重複裡配置順序隨機打散；另量只算、只載兩條參考線。
- **雜訊與判勝門檻**：δ＝每格「各 process 中位數的 (最大−最小)÷整體中位數」的最大值；δ*＝max(5%, δ)。Llama 2.97% → δ* 5%；Qwen 9.43% → δ* 9.43%〔實測 noise〕。

### P.2.6 判準（事先登記）

- **品質 ε（非劣性）**：主任務所有列（兩輪合併），X 對 E0 的配對正確率差，以「題」為單位 bootstrap 10,000 次，95% CI 下界 > −2 個百分點；而且每個任務族、每一輪的點估計掉幅 ≤ 5 個百分點。四種情境（A、B 閒、B 忙、B 閒→忙）都要過。E1 對 E0 的 CI 半寬 > 1.5 個百分點時先加題，不判「沒過」。
- **速度不輸**：每個（頻寬, GPU 狀態）格子，X 的還原時間中位數 ≤ 最快的 25% 混合配置 ×（1＋δ*）。
- **停損規則**：K0（低精度對還原時間沒有賺頭）、K1（均勻就夠）、K1s（保護 sink／最近就夠）、K3（同樣 8 bit 換格式就夠）、K2（在均勻不夠的那一階，位置不比隨機好）。兩個模型怎麼合併、精度階梯（FP8 → INT4，只走一階）照 [03 §1.1、§2.5](../precision_20261013/03_plan_h200.md)。
- 所有判定由 `code/m10_analyze.py` 算，程式在看到任何低精度答對率之前就 commit。
