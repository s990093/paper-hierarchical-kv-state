## 3. 還活著的線索（照「多快能判生死」排序）

### A. 真實 vLLM 在 MI300X 上，開了 CPU 卸載反而變慢（D2 的附帶發現）
同一個工作負載，比較「卸載關掉」和「CPU 卸載 50%」〔實測，vLLM 0.28，Llama-3.1-8B，單一 seed〕：

| 負載 | 同時幾個請求 | 回來請求等待時間中位數：關掉 → 開 50% | 第一輪等待時間：開 ÷ 關 |
|:--|:--|:--|:--|
| chat | 1 | 0.88 → 1.63 s（**慢 1.9 倍**） | 1.28 |
| doc | 1 | 2.26 → 1.11 s（快 2 倍，唯一有幫助的一格） | **1.96** |
| doc | 4 | 6.75 → 7.43 s | 1.34 |
| doc | 16 | 43.7 → 67.0 s（**慢 1.5 倍**；而且回來請求 100% 是重算，卸載完全沒用到） | 1.48 |
| doc＋NFS 層 | 4 | 回來請求最久等了 83 s 等資料搬回來，重算只要 2–7 s | — |

- **為什麼有意思**：這是真實系統「不看 κ」的證據。它寧可等慢的層，也不重算；存的動作本身也拖慢了新請求。
- **原因**：NOT_MEASURED。agent 的事先判準（等待寫完的時間）是 0，所以不是「擋住」，是別的開銷。
- **注意**：只有一個 seed。9 個 run 裡 7 個被 gpu_guard 標記，都是已知的假警報型態（自己的 process 結束那一刻出現 pid −1），但接受規則是看到標記之後才寫的。時間數字要重跑才能當定論。
- **下一步（約 1 天 GPU）**：重跑 3 個 seed；用 profiler 找出開銷在哪（D2H 複製？同步？）；查 vLLM 上游有沒有已知 issue。如果原因是 ROCm 特有的，修好它可能就是一個工程貢獻。

### B. 換一把尺：能耗 κ、成本 κ（D8 第 1、2 名）
- **能耗**：重算耗電，等待也耗電。如果 GPU 重算時的功率是等待時的 1.6–3.2 倍，CPU 層最省電的會是「只載入」，NFS 層才是 Cake，和省時間的答案不同。
- **最快判生死**：用 `amd-smi` 的能量計數器量兩個功率值，約 1 天。主機整機的耗電讀不到，只能量 GPU 的。
- **成本**：KV 版的「五分鐘規則」，把「不存、用時重算」當成一層來算錢。主要是算術，不用 GPU。
- **前作**：MatKV（ICDE'26）只算了 SSD 的 7 W，沒算 GPU 等待時的耗電〔D8 卡片，部分只讀摘要〕。

### C. 預測哪些資料會再被讀，以少寫 SSD（D4）
- 真實 trace 裡 75–78% 的 block 寫了就沒人再讀。常見的「讀第 2 次才存」規則會錯過 17–42% 的重用。
- 但只要 CPU ≥25% 工作集，「完全不寫 SSD」就離最佳不到 2%。所以只有 CPU 很小時才有價值。
- 這是「准入預測」的問題，flash cache 領域有很多前作（例如 LPC），需要再查新穎性。

### D. 負面結果／測量型論文（D3 的建議）
- 主要訊息：「讀取端會自己調整（Cake）時，寫入時放哪一層幾乎不重要。贏家由使用者回來的順序決定，不是由 κ 決定。」
- 證據：第一階段、08、第 1 輪（含 GPU 確認 0／5），加上這 8 個方向。

### 窄的、暫時擱著的
- D5(b)：混合 SSM 的每層檢查點密度。只對分支型工作有意義，要等 D4 那類資料先證明分支常見。
- D6：要定案只差一個不傷品質的量測：INT8 轉回 BF16 一個 chunk 要多久（GPU 30 分鐘）。≤1 ms 就判死路。

## 5. 過程中的偏離與問題（照實列）

- **D1**：事先判準的結果是「有看頭」（5／192）。agent 修了對手的兩個程式錯誤後變 0／192：延後版用的規則和候選不同；丟資料的順序寫反。之後又加了兩個新對手。這正是反方審查說過的偏誤：「候選一贏就加對手」。兩個結果都列在 D1 §0。
- **D4**：判定取決於對手集合。文字列了 7 個，程式裡放了 25 個。而「7 個」那次是在看過「25 個」的結果之後才算的。
- **D2**：gpu_guard 的接受規則是看到標記之後才寫的；結果只有一個 seed。
- **D8**：判準寫在查文獻之後；分數是自評。
- **D7**：寫入量超過預算，上限 150 GiB，實際約 161 GiB，檔案都已刪除。
- **D5**：一個子 agent 把原始碼 clone 進 repo 根目錄，約 15 秒後移走。我確認過根目錄乾淨。
- **D3**：正式 run 之前跑過一次 smoke，先看到了結果；之後沒有改規則。
- **工具問題**：`m7run`／`runsh` 的參數不能含空白、括號或引號，否則 `cmd.sh` 會被拆壞（D4、D6、D8 都踩到）。要修 `runsh`。
