## 1. 主線 B（資源感知的還原規劃）

### 1.1 最強的拒稿理由

> 作者主張還原成本隨 GPU 爭用而變，所以要線上規劃。但這個爭用是服務引擎自己排出來的：引擎決定了還原和誰同時跑，最簡單的解法是替還原固定預留一些 SM（Tutti 用 green context，vLLM #42212 固定 12 個 SM），不需要線上規劃。作者的「格式翻轉」只在合成的 matmul 背景下出現；真實服務以 decode 為主，是頻寬型，作者自己量到頻寬型背景不翻。翻轉還依賴低秩重建這種生產系統沒在用的格式；只用 FP8、INT4 時作者自己的 X3 STOP-0 也沒有翻。實驗是 7–8B 模型、單卡、Slurm 下看不到鄰居。新意是 Cascade（預算切分）、Bidaw（依大小排序）、vLLM #42212（選路）、py-kvcache（break-even）的組合。

### 1.2 逐點回應

| 拒稿點 | 計畫有沒有擋住 | 回應或改動 |
|:--|:--|:--|
| 固定預留 SM 就夠 | 部分 | X4 已把「靜態 green context／MPS 預留」列為對照。**要加一條事先寫死的判讀**：如果最好的 SM 比例在各種背景下都一樣，固定預留就是答案，照實報告，主張縮成「該預留多少」的量測 |
| 真實服務是 decode 為主，頻寬型不翻 | 部分 | B0 的背景有 decode、chunked prefill、混合批次三種。〔判讀，待驗〕在 P/D 分離的部署裡，回來的請求在 **prefill 節點**還原，那裡的背景就是算力型的 prefill；這正是會翻的區域。**加一格「prefill 節點」背景**：連續的 chunked prefill，不混 decode |
| 翻轉依賴生產不用的低秩格式 | 部分 | B 的動作集不只格式：還有切點、copy engine 或 SM 搬運、SM 配額、順序。**B0 要分開報**「只用 FP8、INT4、BF16（生產格式）時，排序會不會因爭用而變」。NVFP4 在 SM90 走軟體反量化（L8c [R6]），也加進動作集 |
| 小模型、單卡、看不到鄰居 | 部分 | X5 加 ≥30B 的模型；Slurm 的污染照 `H200_SLURM.md` §5.3 處理（配對、隨機順序、≥6 次、`squeue -w` 快照）。多卡、P/D 分離不在這次範圍，寫在限制 |
| 只是四篇的組合 | 部分 | 四篇都是靜態或單一訊號，全部放進 X4 當對照；另加「單一使用率純量 vs 資源向量」，證明需要向量。py-kvcache 有搶先風險，所以 HotOS（2/1）先占位置 |

## 2. 副線 A（讀回時的查詢導向分級還原）

### 2.1 最強的拒稿理由

> 一份漸進碼、由查詢決定每塊讀多深，ReadKV、Fathom 都做了；AnchorKV、MiKV 早就「不讓任何 token 離開 softmax」。作者只是把它搬到讀回時。而且作者自己的資料顯示 8 倍均勻壓縮已經接近無損（Qwen −0.7），能贏的只剩極端倍數。讀回時要先讀 base、跑一次問題、再讀 refinement，在慢層上多了一次往返，排隊時可能抵消省下的位元組。在粗版上算的 query 會跑掉，挑塊準度沒保證。最後，答案取決於挑了哪些塊，同一個問題在不同預算下答案不同。

### 2.2 逐點回應

| 拒稿點 | 計畫有沒有擋住 | 回應或改動 |
|:--|:--|:--|
| 表示法已有人做 | 是 | 已承認（04 A 段、03 §1）；主張只放在讀回邊界才有的問題：query 不精確、塊為單位、慢層位元組、期限、和 Cake 合用。ReadKV 式「同碼查詢無關」是 A0 的必要對照 |
| 8 倍均勻已經夠好 | 是 | GA0-STOP 事先寫死；找不到均勻不夠的區域就停 |
| 慢層多一次往返 | **沒有** | **加進 A2**：量「base 讀完 → 問題 prefill → refinement 讀完」的關鍵路徑，和全部一次讀完比；refinement 的讀取和問題 prefill 管線化。NFS 下要另外量排隊（I3g 的教訓：等待是排隊爆出來的） |
| 粗版上的 query 會跑掉 | 是 | A0 的 EXACT-Q 對 BASE-ATTN 就是在量這件事；這也是 A 最乾淨的新知識 |
| 答案取決於挑塊 | 部分 | A 的主設定是固定預算、對同一個問題結果固定；隨負載改預算的 E 只當延伸，並寫明違反「命中與不命中輸出相同」的產品承諾 |

## 3. 由這輪檢查新增到 05 的項目

1. B0 加「prefill 節點」背景（連續 chunked prefill）。
2. B0 分開報「只用生產格式」時的排序變化；動作集加 SM90 軟體反量化的 NVFP4。
3. B 的判讀加一條：最好的 SM 比例若不隨背景變，結論改成「固定預留多少」。
4. A2 加「兩段讀取的關鍵路徑」量測，NFS 另量排隊。
