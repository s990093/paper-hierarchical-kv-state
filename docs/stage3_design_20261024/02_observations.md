## 0. 一句話

前三個階段反覆出現同一件事：**決定 KV 待遇需要的資訊，在寫入時還不存在，要到讀取那一刻才出現**。這些資訊包括新問題要讀哪些塊，以及 GPU 當下被誰佔用。第三階段該做的，是把「讀取時才有的資訊」用起來。

## 2. 還有三個「量測環境」上的教訓（會直接影響第三階段怎麼量）

1. **「GPU 忙」要用空間共用來模擬，不能用兩個 process 輪流用時間片**。H200 沒開 MPS 時，背景和還原是時間片輪流：每個 block 要動一次 GPU，就固定多約 3.7 ms（`STAGE2_H200_VS_MI300X.md` §0）。真實的服務引擎裡，還原和 decode 在同一個 process 的不同 stream 上並行。第三階段一律用「同 process 雙 stream」或 MPS。
2. **背景要像真的服務**。之前的背景只有純 matmul（算力型）和純複製（頻寬型）兩種極端。真實的 decode 是頻寬型，chunked prefill 是算力型，混合批次介於兩者之間。O8 的翻轉在真實背景下還會不會出現，**還沒量**。
3. **模擬的排序可信、絕對值不可信**。I3g 實測／模擬為 0.55–7.85 倍，X3 決策圖低估 5–26%（STOP-3）。所以第三階段的主結論一律用實測，模擬只拿來篩格子。
