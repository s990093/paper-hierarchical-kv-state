### 6.1 第二階段：在「預算相同」的條件下比較精度

混合精度（例如「10% 的 chunk 用 FP8」）真正的用處，是控制「位置」這個變因：先把總預算固定，再比較「要降精度的那些 chunk 怎麼挑」。

| 組別 | 哪些 chunk 降精度 | 回答什麼 |
|:--|:--|:--|
| 全 BF16 | 都不降 | 基準 |
| 全部 FP8 | 全部 | 最簡單的降精度。M1 已實測 FP8 KV 讓容量剛好變 2 倍 |
| 隨機 X% FP8 | 隨機挑 X%，不看位置 | 對照組：如果位置不重要，結果應該和下一組差不多 |
| 依位置 X% FP8 | 依位置挑 X%，例如前段 | 位置是不是真的重要 |
| 依位置、預算相同 | 讓總位元組數等於「全部 FP8」，依位置分配 BF16、FP8、INT4 | 依位置分配能不能贏過「全部 FP8」 |

- **預算要對齊**：X 用「總位元組數相同」或「品質損失 ε 相同」來對齊，不同預算的組別不能互相比。X 的掃描點（例如 10%、25%、50%）在第二階段開跑前寫死。
- **品質**：前段的 token 通常特別受注意，例如 StreamingLLM 的 attention sink；MuKV 的圖 5 也觀察到越早的 token 注意力越高。所以把前段降精度，可能比隨機降精度更傷品質。開頭幾個 sink token 一律保持全精度（EVAL_FOUNDATIONS §10.5）。
- **讀取成本**：讀 FP8、INT4 的 KV 要多做反量化，這個成本要先實測（EVAL_FOUNDATIONS §10.5 第 6 點）。
