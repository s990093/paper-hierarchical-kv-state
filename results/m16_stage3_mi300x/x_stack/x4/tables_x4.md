## 事先寫死的判定與和計畫不同的地方

- **Q-A**：（計畫 §3）某一軸加在「xKV＋INT4」上，同倍數帶（±10%）內答對率（TF 的 Δgold_lp；生成的配對差）沒有比「把同樣的位元組省在降秩或係數位元上」差 → 這一軸值得疊；差 → 不值得。計畫沒寫統計門檻，這裡寫死成：帶內「有這一軸的最好配置」−「沒有這一軸的最好配置」的逐題配對差（bootstrap 10,000 次）95% CI 上界 < 0 → 差（不值得疊）；其他 → 沒有比較差（值得疊）。無損：真實壓縮比（zstd:3）≥ 1.05 倍 → 值得疊（在慢連線上；速度由 X3 決定）。
- **Q-B**：（計畫 §3）每個目標倍數下 TF 最好的分法進 X4b 生成；生成的最佳分法（帶內 X4b 配置裡答對率最高的）就是那個倍數的「最佳配比」。最佳配比在 ε 內的最大倍數＝極限。
- **limit**：（計畫 §3）極限倍數 B*_ε（每模型、每上下文）＝ε 內（生成答對率對 E0 的配對差 95% CI 下界 ≥ −2 個百分點）最小的位元組比；另報 B*_99、B*_99.9（MLPerf 式：答對率 ≥ E0 的 99%／99.9%，點估計）。題數 < 48 的格子寫 INCOMPLETE，不報倍數。
- **stack**：（計畫 §3）「疊加優於單降秩」：同一個倍數帶（位元組比相差 ±5% 內）最好的「秩＋量化」配置對最好的「只降秩」配置的生成配對差 CI 下界 > 0 → 成立；沒有可比的一對 → NOT_COMPARABLE。
- **long**：（計畫 §3）128K（256K）時前緣配置對 E0 的差在 ε 內 → 撐住；超出 → 寫出在哪個倍數開始掉。
