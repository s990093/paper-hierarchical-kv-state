## 事先寫死的合併方式與規則

- **design**：X2b：新題 seed 63000 起（T2–T5 各 48 題＝192 題），和 X1（60000）、校準（61000）、X2（62000）不重疊；32K；配置＝code/m16_xstack_combos_v2.json 的 x2b（協調者列的 10 個＋只用第一版 X2 決定的池子缺口單一方法：兩個模型的 q:int2_kivi、Qwen 的 xl:k22:v34；Llama 11 個、Qwen 12 個；roles／budgets 照第一版 x2_selection.json）。
- **pairing**：合併（X2＋X2b）：配置集合 C＝X2b 的配置裡、第一版 X2 有量的（≥90% 的 X2 題有這個配置；X2 每一層都是全部 96 題，少數題缺＝那題寫到一半）；題目＝E0 與 C 的每個配置都有的題（每題所有配置都有，逐題配對；被排除的題數另列）。X2b 有、X2 沒有的配置（例如 Qwen 的 xl:k22:v34+q:int8_token）只在「只用 X2b」報。
- **rules**：M1／M2／完整性／MLPerf 照第一版寫死的規則（STOP_TEXT 的 M1、M2、completeness、MLPerf；judge_x2 原樣）重算，只是單一方法池與組合池限制在 C。:cal 的配置不進任何池（校準基底另判，見 xlcal）。
- **pool_gap**：池子缺口（事先寫死；只標註、不改判定）：第一版池子裡、不在 C 的配置——單一方法若位元組比 < 合併後的 B*(單一)（或 B*(單一) 不存在）而且只用 X2 的 CI 上界 ≥ −ε（多量可能過 ε）→ 合併的 r 可能偏小（偏向 GO）；組合同理（位元組比 < B*(組合)（或不存在）且 CI 上界 ≥ −ε）→ r 可能偏大（偏向 NO-GO）。
- **variants**：A＝只用 X2、第一版的整個池（重現第一版）；B＝只用 X2、池子限制在 C；C＝只用 X2b（池子 C；X2b 獨有的配置另列）；D＝X2＋X2b（池子 C）。主要讀 D；A→B＝限制池子的效果、B→D＝加題數的效果、C＝獨立重複。
- **feasible_v2**：v2/x2_feasible.csv：每個配置用能拿到最多題的那一組：在 C → D；只在 X2b → C；其他 → A（第一版的題）；欄位 source 標明。
- **complete**：X2b 每個模型 192 題齊全才算完成（x2b_complete）；判定本身照第一版的 ≥48 題規則。
- **第一版 M1**：（L5d §6.3）每個家族在 ε 內（生成答對率對 E0 的配對差 95% CI 下界 ≥ −2 個百分點）能到的最小位元組 B*；r＝B*(最好的組合)／B*(最好的單一方法)。兩個模型都 r > 0.95（沒有組合過 ε 也算）→ NO-GO（疊加沒有加乘）；沒有模型 < 0.85、但有 0.85–0.95 → 停下來問人；任一模型 r < 0.85 → GO（進第三階段）。
- **第一版 M2**：（L5d §6.3）每個預算：主要組合（X1 事先選的前緣第 1 名）− 最好的單一方法（X1 選的），生成答對率配對差。E0 − 最好的單一方法 < 2 個百分點的預算記成「沒有空間」；有空間的預算全部「差 < 2 個百分點或 CI 含 0」→ 支持 NO-GO。Holm 校正（3 預算 × 2 模型，單邊 α＝0.025）。
- **第一版 completeness**：（L5d §6.3）最好的組合在 M1／M2 贏，但天真疊加（naive）本身已經一樣好（naive − 主要組合的 CI 含 0 或 ≥ −ε）→ 結論改寫成「疊加有用，但不需要聯合分配」。
- **第一版 MLPerf**：（L6 §5.2，只報、不改判定）MLPerf 式門檻：答對率 ≥ E0 的 99%（以及 99.9%），點估計；另報同樣門檻下的 B*。
