## 事先寫死的設計與判定

- **design**：xKV 的基底事先用校準題算好（seed 61000 起的 8 題，和 PCA 校準同一套、和所有評測題不重疊；每 4 層一個窗口、K（逆 RoPE）／V 各一個；不去平均的 ΣZᵀZ 的前 R 個特徵向量），所有題共用。比較＝同一題、同一個行程裡，校準基底版 vs 每題 SVD 的同名配置（同秩、同係數量化）。
- **tf**：TF 篩選（X1 的前 12 題／任務＝48 題）：只報告、不判定。每題 SVD 的 TF 取自 X1 同一題的列（跨 run；E0 是否逐值重現另列），另在同一個行程量 xl:k11:v17 當錨點（同 run 配對＋和 X1 的重現）。
- **rule**：判定（生成答對率、X2 的 96 題、逐題配對：校準 − 每題 SVD，bootstrap 10,000 次的 95% CI）：CI 上界 < −2 個百分點 → MUST_PER_ITEM（必須每題算 SVD）；CI 下界 ≥ −2 個百分點 → CAN_PRECOMPUTE（可以事先算好基底）；其他 → UNDETERMINED（題數不夠分辨）。
- **aggregate**：每個模型：三對都 CAN_PRECOMPUTE → CAN_PRECOMPUTE；任一對 MUST_PER_ITEM → MUST_PER_ITEM（至少那個秩要每題算）；其他 → UNDETERMINED；題數 < 48 → INCOMPLETE。整體：兩個模型都 CAN → CAN；任一模型 MUST → MUST；其他照實寫。
- **bytes**：同秩時，校準版的每請求位元組＝每題 SVD 版減掉每題的基底（基底跨請求共用，列在 bytes_shared，大小和每題的基底相同）。所以 CAN_PRECOMPUTE＝同秩不比每題 SVD 差、而且每請求更省。攤提〔算術〕：共用基底 S 由 N 個請求（或同一個請求的多次還原）分攤，每請求多 S/N；N＝1 時正好等於每題 SVD 版（打平點恆為 1），report 列 N＝1／8／64 的攤提後位元組比。實際部署只要存最高秩的一份基底（低秩取前幾欄），S 以最高秩那份為準會更大，這裡照每個配置自己的秩算。
